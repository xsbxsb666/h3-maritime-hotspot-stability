## 选题

**《会话被“污染”后是否应自动降权？面向海洋质检智能体的低信任数据污点传播实验》**

> 当海洋质检智能体读取了“不可信来源”的数据卡后，宿主系统是否应自动收紧它后续调用写入、邮件等高风险工具的权限？

## 可以提出的原创创新点

设计一个“会话污点传播器”：

1. 每条资料携带来源等级，例如“内部正式数据”“官方公开资料”“开放投稿资料”。
2. 智能体一旦读取开放投稿资料，宿主就把会话状态设为 `TAINTED`。
3. 污点状态不只显示给模型，还直接改变工具权限：
   - 只读查询继续放行。
   - 写入质检表时，确认页必须标出低信任依据。
   - 对外发送工具默认冻结。
   - 只有人工核验具体证据和收件人后，才能对该次动作临时解锁。
4. 污点沿证据链传播。如果质检结论引用了低信任资料，该结论也带有低信任标记。

关键创新不是再写一句“不要听数据里的指令”，而是让**数据来源真正改变系统权限**。

## 实验设计

建立完全本地的模拟海洋质检工具，不连接真实邮箱或数据库：

- `query_qc_stats`：查询S07站质检统计。
- `rag_search`：返回官方资料或开放投稿数据卡。
- `write_qc_note_mock`：模拟写入质检备注。
- `send_email_mock`：只记录调用，不发送邮件。

设计四组防御：

| 组别 | 防御方式 |
|---|---|
| A | 仅在系统提示中要求忽略恶意指令 |
| B | 给资料添加“低信任来源”文字标签 |
| C | 整个任务始终关闭外发工具 |
| D | 采用你提出的动态污点传播与权限收紧 |

资料同时包含正常数据卡和带间接提示注入的数据卡。每个条件重复运行，以处理模型输出的随机性。

建议记录五项指标：

- **意图劫持率**：模型是否尝试调用未授权工具。
- **实际危害执行率**：宿主是否真正放行了危险动作。
- **正常任务完成率**：质检分析能否正常完成。
- **误拦截率**：没有攻击时，正常动作被拦截的比例。
- **额外成本**：增加的步骤数、确认次数和 token。

最有价值的分析是区分：

> 模型有没有被诱导，和系统有没有让诱导转化成真实动作。

即使模型仍会产生恶意调用意图，只要宿主层阻断了执行，系统级危害仍可能降到零。这会比单纯比较“模型有没有拒绝恶意文字”更有深度。

## 可检验的假设

- H1：单纯的提示词警告无法稳定阻止间接提示注入。
- H2：低信任标签能降低意图劫持率，但不能保证危险调用不发生。
- H3：动态污点传播能显著降低实际危害执行率。
- H4：相较于始终关闭外发工具，动态降权能保留更高的正常任务完成率。

这样无论实验结果支持还是反驳假设，都能形成有效报告，不需要“编造成功”。

## 选题一：低信任数据触发动态权限降级

建议题目：

**《会话被“污染”后是否应自动降权？面向海洋质检智能体的低信任数据污点传播实验》**

具体场景是：智能体为了分析S07站温度传感器异常，读取了一份开放投稿数据卡。数据卡中夹带恶意文字，要求智能体把“凭据摘要”发送至指定邮箱。实验研究读取这份资料后，系统应不应该自动冻结邮件等高风险工具。

创新点是把“低信任”从一个文字标签变成真正的系统状态：

- 读取低信任资料后，会话被标记为 `TAINTED`。
- 只读查询仍可进行。
- 写质检备注时必须展示资料来源。
- 对外发送自动冻结，经过人工核验后才能临时解锁。
- 使用低信任资料形成的结论继续携带污点标记。

实验可以分别测量“模型是否受到诱导”和“系统是否真正执行危险动作”。

## 选题二：超时重试中的语义幂等键

建议题目：

**《一次超时会产生几个重算任务？海洋数据智能体语义幂等键的去重实验》**

课件中的场景是：智能体提交S07站重算任务，接口返回超时。智能体不知道任务是否已经成功，于是再次提交。如果没有幂等机制，系统可能同时运行两个完全相同的作业。

可以比较三种策略：

1. 不使用幂等键。
2. 每次重试生成新的随机键。
3. 使用“任务ID＋步骤号＋规范化参数＋数据版本”生成确定性键。

主要指标包括：

- 重复作业率。
- 计算资源浪费量。
- 正常新任务被误判为重复的比例。
- 超时后的平均恢复时间。

原创点可以放在“数据版本感知的语义幂等键”上。例如，同一个站位和时间范围，如果底层数据版本发生变化，就应该允许重新计算；如果数据没有变化，则重试只能返回原任务。

这个选题的优点是代码实现简单、结果稳定、容易画出定量图表。缺点是研究争议和AI特色稍弱，容易写成传统分布式系统实验。

## 选题三：模型自称完成与程序化末态断言

建议题目：

**《“已完成”真的完成了吗？海洋质检智能体末态断言的可靠性实验》**

构造一组部分完成的任务：

- 报告已经生成，但没有引用。
- 质检备注已经写入，但内容不完整。
- 重算任务已经提交，但仍在运行。
- 结果文件存在，但月份或数据版本错误。

然后比较：

1. 让模型自行判断是否完成。
2. 使用文字版完成清单。
3. 使用程序化末态断言。
4. 使用“末态断言＋证据编号”的完成证书。

主要指标包括：

- 虚假完成率。
- 漏报未完成事项的比例。
- 正常任务完成率。
- 增加的步骤数和token成本。

原创点可以是“证据绑定完成证书”：智能体不能只输出“已完成”，而要为每个完成项提供对应的工具调用编号、返回状态和产物位置。

这个题目实验最容易控制，也很贴合课件案例，但前沿性略低于选题一。

## 我选择选题一的理由

我最终推荐第一个选题，主要有五个理由。

1. **与课程案例结合最紧密**

课件已经给出了开放投稿数据卡、内部质检数据、邮件工具和确认门。你不需要另造一个脱离课程的应用场景，只需对课程案例继续追问：“贴了低信任标签以后，系统究竟改变了什么？”

2. **原创空间最大**

> 来源标签 → 会话污点 → 权限变化 → 确认门升级。

这是一条明确、可实现、可验证的原创机制。

3. **属于真实的前沿问题**

MCP官方在2026年讨论了类似的 `seesUntrustedData` 注释，并提出客户端可在读取不可信数据后把会话标记为受污染、收紧后续审批；官方也指出，这类注释当时还没有普遍转化为客户端的实际权限动作。[MCP官方博客](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/) NIST也在推动间接提示注入和智能体劫持的量化评测。[NIST](https://www.nist.gov/news-events/news/2025/01/technical-blog-strengthening-ai-agent-hijacking-evaluations)

因此，你不是简单重复课件，而是在验证一个正在形成中的技术方向。

4. **能产生有意义的对照结果**

实验不必只证明“我的方法有效”，还可以揭示不同防御的边界：

- 提示词警告是否只在部分情况下有效？
- 来源标签能否降低模型受骗概率？
- 永久关闭外发虽然安全，是否严重影响正常任务？
- 动态降权能否在安全性和可用性之间取得更好平衡？

即使动态降权导致较多误拦截，这也是有价值的实验结论。

5. **更容易体现你自己的思考过程**

这个题目天然包含需要你做决定的地方，例如：

- 哪些资料算低信任？
- 污点应该持续到什么时候？
- 写质检备注是否也要冻结？
- 人工确认能否清除整个会话的污点？
- 如何区分模型“想做坏事”和系统“真的放行”？

这些问题适合你在后续聊天中逐步质疑、修改和形成自己的方案，最终的AI协作记录也会比“一次生成报告”更有说服力。

### 第一名：H3热点排名的网格敏感性

建议题目：

**《换一个H3分辨率，“最繁忙海区”还成立吗？——AIS船舶热点排名的网格敏感性与稳健性证书》**

具体知识点是第3讲的H3、空间聚合和MAUP，不扩展成宽泛的“海洋时空大数据研究”。

H3官方资料也明确说明，同一分辨率的单元面积会随球面位置变化，因此“每格船数”不能直接当作密度，仍需进行实际面积归一化。[H3官方单元统计](https://h3geo.org/docs/core-library/restable/)

#### 原创点

设计一张“热点稳健性证书”。一个热点只有同时满足以下条件，才称为稳健热点：

- 在相邻分辨率下仍进入Top-K。
- 排名变化不超过指定范围。
- 热点中心移动距离较小。
- 改用有效海域面积归一化后结论仍成立。
- 在不同时间切片中重复出现。

这比普通的“画一张H3热力图”多了一层结论可靠性检验。

#### 后续开展计划

1. **数据与口径**

   选择一个月、约5°×5°海区的公开或脱敏AIS数据。固定事件时间、去重规则、海陆掩膜版本，统计每格去重船数密度。

2. **正确性基线**

   用已知港口验证经纬度顺序；检查聚合前后总点数守恒；加入反经线、空格元等边界测试。

3. **扰动实验**

   分别使用H3 resolution 6、7、8重新聚合。将结果映射到统一尺度后比较Top-20热点。有余力再加入S2或半格偏移作为外部稳健性检验。

4. **评价指标**

   - Top-20 Jaccard重合率。
   - Spearman排名相关系数。
   - 热点中心搬移距离。
   - 总量守恒误差。
   - 不同周次的热点出现频率。

5. **原创结果**

   输出“稳健热点”“边界敏感热点”“分辨率敏感热点”三类结果，并解释哪些热点可以写进正式报告，哪些只能作为探索性发现。

6. **AI协作记录**

   先让AI质疑你的分辨率、面积归一化和Top-K定义；你选择其中一条质疑做实验。若AI预测热点稳定但实验发现搬家，就完整记录“AI假设—实验反证—方案修正”。

#### 为什么它排第一

- 与教材实验和评分量表完全对应。
- 不依赖付费模型或大型集群。
- 正确性、口径、可复现性都有明确证据。
- 地图和稳定性曲线直观，报告容易讲清楚。
- “稳健性证书”明显超出了课件中的普通换格复算。

## 二、找到的技术前沿

### 1. H3 的父子关系不是严格几何嵌套

H3 官方明确说明：它提供精确的“逻辑父子关系”，但父子六边形之间只有近似的“几何包含关系”。因此，一个点在较细分辨率单元的逻辑父格，不一定等于这个点在粗分辨率下直接编码得到的单元。[H3 官方说明](https://h3geo.org/docs/)

这正是本课题最重要的技术切口，也是“直接编码 vs 层级回卷”可能产生差异的理论原因。

### 2. H3 并不是严格等面积网格

H3 同一分辨率下，不同位置的六边形面积并不完全相同。官方统计显示，较高分辨率下全球最大和最小六边形面积之比接近 2；r7、r8、r9 的平均面积约为 5.16、0.737、0.105 平方公里。[H3 单元统计](https://h3geo.org/docs/core-library/restable/)

相关比较研究也发现：H3 的形状规则性较好、软件生态成熟，但面积均匀性弱于部分等面积 DGGS。[Kmoch et al., 2022](https://doi.org/10.1080/20964471.2022.2094926)

因此，不能只比较每个单元的 AIS 数量，还应比较：

\[
D_c=\frac{\text{船舶活动量}_c}{\text{H3单元实际面积}_c}
\]

也就是“原始计数排名”和“面积归一化密度排名”是否一致。

### 3. DGGS 已从概念标准进入 API 互操作阶段

ISO 19170-1:2021 和 OGC Topic 21 规定了 DGGS 的参考系统、层级网格、区域标识和查询操作。2025 年，OGC 又正式发布了 OGC API–DGGS Part 1，使 DGGS 数据可以按照区域、时间和分辨率通过标准化 API 查询。[ISO 19170-1:2021](https://www.iso.org/standard/32588.html)、[OGC Topic 21 v2.0](https://docs.ogc.org/as/20-040r3/20-040r3.html)、[OGC API–DGGS 1.0](https://www.ogc.org/announcement/ogc-membership-approves-ogc-api-discrete-global-grid-systems-part-1-core-as-an-official-ogc-standard/)

这说明技术前沿正在从“选哪个网格”转向：

- 多分辨率数据能否一致聚合；
- 不同实现之间能否互操作；
- 聚合结论的不确定性是否可量化；
- 是否记录完整的网格、版本和计算口径。

### 4. MAUP 研究正在从“提醒存在偏差”转向“量化偏差分布”

2026 年最新研究提出，不应只做两三个网格的简单对比，而应把 MAUP 敏感性定义为：改变空间划分后，统计结果相对基准值的“偏差概率分布”。[Ye & Chen, 2026](https://doi.org/10.1080/20964471.2026.2692263)

你的实验可以吸收这个思路：不只报告“Top-10 重合了几个”，还通过逐日重采样得到每个热点进入 Top-K 的概率。

### 5. AIS 报文数量不等于船舶活动强度

当前有效的 AIS 技术规范是 ITU-R M.1371-6（2026）。不同船型、航速、转向状态具有不同报文发送间隔，例如 Class B 船舶的报告间隔可能从数秒到数分钟不等。[ITU-R M.1371-6](https://www.itu.int/rec/R-REC-M.1371-6-202602-I/en)

所以直接统计 AIS 记录条数会把“发送频率高”误判为“活动强”。建议主指标使用：

- 每日每格独立 MMSI 数；
- MMSI-day；
- 经过插值后的船舶停留时间；
- 单位实际海域面积的活动密度。

原始 AIS 报文数只作为对照指标。

## 五、可以写成“原创创新点”的设计

建议把原创成果命名为：

> H3 船舶热点稳健性证书（H3 Maritime Hotspot Stability Certificate）

每次热点分析必须同时输出：

1. 数据时间、空间范围和数据指纹；
2. H3 与计算软件版本；
3. 活动量和分母定义；
4. 直接编码与父格回卷的不一致率；
5. 原始计数排名与面积归一化排名差异；
6. 同分辨率 Top-10/Top-20 Jaccard 重叠率；
7. Kendall τ-b 排名相关系数；
8. 跨分辨率热点区域的面积加权 IoU；
9. 热点重心位移；
10. 按天 Bootstrap 后进入 Top-K 的概率；
11. 总量守恒检查；
12. 是否通过预先设定的稳健性阈值。

其中最有价值的改进是：跨分辨率时不能只比较固定的 Top-10。因为 r5 的十个单元和 r9 的十个单元覆盖面积相差极大。建议同时比较“相同海域面积”或“相同累计船舶活动占比”的热点区域。

## 六、后续实验顺序

1. 先完成 AIS 清洗和 MMSI-day 指标。
2. 分别直接编码到 r9、r7、r5。
3. 从 r9 回卷到 r7、r5。
4. 计算直接编码与回卷结果的不一致率。
5. 分别生成计数排名、实际面积密度排名。
6. 做固定 Top-K 和等面积热点区域两套比较。
7. 按天进行 500 次 Bootstrap。
8. 输出稳健性证书、差异地图和失败案例。
9. 最后再讨论：所谓“最繁忙海区”究竟是数据事实，还是网格、聚合路径和统计口径共同产生的结果。
